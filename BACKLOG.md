This document is the authoritative backlog and v1.1 candidate boundary.

Priority is planning input, not authorization to work. Nothing here is approved for implementation
until the owner selects the v1.1 scope. Effort is deliberately not estimated.

the 2026-09-28 audit), `LIKELY` (strong documentary evidence, not directly exercised), `UNCERTAIN`

## v1.1 candidate boundary

Proposed as a coherent, limited maintenance and trust release — not a return to broad feature
development. The owner selects the final scope.

**Strong v1.1 candidates**

- LB-B01 automated database backups — recurring recovery point for live learner data.
- LB-B02 monitoring and alerting — detect failure without waiting for a user report.
- LB-B04 account deletion, privacy notice and support route — release-critical surfaces the
  roadmap required for v1.0 and the live product shipped without.
- LB-B03 activate the Profile identity read — small, flag-gated, completes the Profile surface.
- LB-B07 + LB-B08 OTP delivery resilience — a real sign-in failure mode with no user recourse.
- LB-B14 accessibility sweep — the public product has no exercised accessibility evidence.
- LB-B09 reconcile the canonical manifest with the activated state.
- LB-B10 close the public-repository media exposure — the one open P0; owner decision required.
- LB-B21 finish documentation closure in secondary documents.

**Better deferred**

- LB-B12, LB-B15, LB-B16, LB-B17, LB-B18, LB-B19, LB-B20 — platform expansion, commerce and
  AI-factory work already excluded from v1.0; no current evidence supports reconsidering them.
- LB-B11 server-backed progress — meaningful but larger; sequence after the trust items.

**Investigation required before planning**

- LB-B05 synthetic audio — decide whether native-speaker recording is a v1.1 goal, and resolve
  the two recorded transcription discrepancies. Depends on a content/budget decision.
- LB-B06 media out of the application image — depends on the storage decision below.
- LB-B13 Admin operations — scope depends on whether support tooling is needed before growth.

## Owner decisions required

1. **v1.1 scope selection** from the candidate set above; nothing is authorized until then.
2. **Private media storage** — keep media in the application image (LB-B06) or move to object
   storage. This gates the content release model and interacts with LB-B10.
3. **Repository visibility / media distribution** (LB-B10, P0) — all 105 canonical assets are
   anonymously downloadable from the public repository. Options: make the repository private,
   remove media from Git history and serve only through the authenticated route, or explicitly
   accept public Starter media and bind the "no public media" constraint to premium packs only.
   Removing existing files from Git history is destructive and must not be attempted without
   explicit owner authorization.
4. **Audio quality** (LB-B05) — accept the owner-approved synthetic set for v1.1, or fund native
   recording.
5. **Backup retention and cost** (LB-B01) — frequency and retention window for the live database.
