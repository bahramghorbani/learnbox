# برنامهٔ اجرایی پیاده‌سازی طراحی تأییدشدهٔ Admin

- **طراحی مرجع:** `prototypes/admin-ui-v1` روی branch `proto/admin-ui-concept`، کامیت `8b3e050d`.
- **مجوز طراحی:** `docs/product-decisions/PDR-009-ADMIN-UI-DESIGN-FREEZE-AND-BOBO-VARIANTS.md`
  (approved, design frozen).
- **وضعیت این سند:** برنامه است، نه پیاده‌سازی. هیچ مرحله‌ای بدون دستور مالک آغاز نمی‌شود.
- **قاعدهٔ حاکم:** اجرای دقیق طراحی تأییدشده روی Backend موجود. بازنویسی سیستم، طراحی سلیقه‌ای
  جایگزین، و حذف قابلیت موجود ممنوع است.

## قواعد غیرقابل‌مذاکره برای همهٔ مراحل

1. branch طراحی مستقیماً در `main` ادغام نمی‌شود؛ فقط به‌عنوان مرجع بصری خوانده می‌شود.
2. دادهٔ نمایشی prototype (`assets/js/data.js`) هرگز وارد کد محصول نمی‌شود. هر عددی که در UI دیده
   می‌شود باید از API واقعی Admin بیاید.
3. دادهٔ بدون منبع واقعی «در دسترس نیست» نشان داده می‌شود، نه عدد ساختگی (قاعدهٔ `empty.html`).
4. هیچ منطق امنیتی یا تجاری به‌خاطر ظاهر حذف یا تضعیف نمی‌شود: Passkey، سیاست reauth پنج‌دقیقه‌ای،
   محدودیت `is_free`/`price_tomans`، نقش‌ها و مرز دادهٔ زبان‌آموز دست‌نخورده می‌مانند.
5. قابلیت‌های امروز Admin حتی اگر در prototype دیده نشوند حفظ می‌شوند (فهرست در بخش «موجودی»).
6. هر مرحله یک PR مستقل، با CI الزامی سبز، و قابل بازگشت با revert همان PR.
7. استقرار Production فقط با مجوز مالک و فقط Admin؛ learner در هیچ مرحله‌ای redeploy نمی‌شود.

### مرحلهٔ ۰ — پایهٔ طراحی و الگوهای حالت — **انجام شد**

> **وضعیت: کامل.** مجوز مالک ۱۰ اکتبر ۲۰۲۶ («AUTHORIZE STAGE 0»).
>

> هم از قبل پورت شده بود (با scope `.cp-workspace`).
>
> آنچه افزوده شد: الگوهای مشترک Loading/Empty/Error که اصلاً وجود نداشتند —
> `apps/admin/app/components/AdminStates.tsx` (`LoadingState`, `EmptyState`, `ErrorState`) به همراه
> رول‌های `.empty`، `.empty-xl`، `.err-block`، `.err-text`، `.spinner`، `.unavailable` در
> `globals.css`.
>
> **انحراف عمدی از مرجع:** خودِ CSS مرجع شش توکن را مصرف می‌کند که هرگز تعریفشان نکرده
> (`--rose`, `--amber`, `--bg-soft`, `--r-md`, `--lav-soft`, `--lav-line`)؛ پورت کلمه‌به‌کلمه به
> `var()`های حل‌نشده می‌انجامید. این شش مورد به مجموعهٔ کامل توکن‌های همین فایل نگاشت شدند، طبق
> همان قراردادی که `.notice` از قبل استفاده می‌کرد.
>
> سه مصرف‌کننده به الگوی مشترک منتقل شدند (متن نمایشی بدون هیچ تغییر): حالت انتظار
> `AdminAuthGate`، و در `UsersManagement` حالت خالی جدول کاربران، حالت خالی فهرست بسته‌ها و دو
> حالت بارگذاری. کلاس‌های تک‌مصرفی `.users-loading`/`.users-empty`/`.user-packs-empty` حذف شدند.
> بنرهای `.users-error`/`.users-notice` عمداً دست‌نخورده ماندند: آن‌ها notice هستند نه حالت خطای
> تمام‌صفحه، و تبدیلشان کار مرحلهٔ ۵ است. `.splash-error` هم دست‌نخورده ماند چون یک تست موجود آن
> را pin کرده است.
>
> باقی‌ماندهٔ انطباق با مرجع: عرض سایدبار ۲۴۸px در برابر ۱۸۶px مرجع، و grid در برابر flex بودن
> پوسته — هر دو متعلق به مرحلهٔ ۱‌اند و عمداً تغییر نکردند.

- **کار:** چیدمان `ops.html` و `settings.html`. تنظیمات فقط نمایش وضعیت پیکربندی و پرچم‌ها به‌صورت
  خواندنی است؛ ویرایش env از پنل در دامنهٔ این برنامه نیست.
- **وابستگی:** مرحلهٔ ۱.
- **معیار پذیرش:** هیچ راه تغییر پرچم یا secret از UI؛ گزارش حسابرسی بدون افت قابلیت فیلتر.
- **تست:** سوئیت موجود حسابرسی؛ تست اینکه صفحهٔ تنظیمات هیچ متد نوشتنی صدا نمی‌زند.
- **خطر:** افشای مقدار پیکربندی حساس در UI. **کاهش:** فهرست سفید پرچم‌های قابل‌نمایش.

### مرحلهٔ ۱۱ — Responsive و بازبینی نهایی

- **کار:** چیدمان دسکتاپ/تبلت/موبایل برای همهٔ صفحات، بازبینی RTL، دسترس‌پذیری پایه (فوکوس،
  برچسب‌ها، کنتراست)، و مقایسهٔ نهایی با مرجع.
- **وابستگی:** همهٔ مراحل قبلی.
- **معیار پذیرش:** هیچ صفحه‌ای در عرض موبایل شکسته نیست؛ ناوبری با کیبورد کامل است؛ اختلاف‌های
  باقی‌مانده با مرجع در `DEVIATIONS` به‌روزشده ثبت شده‌اند.
- **تست:** بازبینی دستی در سه عرض + اجرای کامل CI.

## خطرهای سراسری

1. **بازطراحی می‌تواند یک گیت امنیتی را بی‌صدا بردارد.** کاهش: هر PR که فایل احراز هویت یا مسیر
   `support/*` را لمس می‌کند باید تست منفی داشته باشد.
2. **دادهٔ نمایشی prototype می‌تواند وارد محصول شود.** کاهش: `assets/js/data.js` هرگز کپی نمی‌شود؛
   بازبینی هر PR برای عدد hard-coded.
3. **از دست رفتن قابلیت‌هایی که در مرجع تصویر ندارند.** کاهش: فهرست «موجودی» این سند معیار است.
4. **تورم دامنه.** کاهش: هر مرحله یک PR، معیار پذیرش بسته، بدون قابلیت جدید محصول.
5. **استقرار Admin، learner را تحت تأثیر قرار دهد.** کاهش: compose جداگانه، فقط سرویس admin.
