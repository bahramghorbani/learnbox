## ۳. طبقه‌بندی مسائل باقی‌مانده

### P0 — مانع استقرار امن

1. **image اجراشدهٔ Admin از candidate عقب‌تر است.** Production کانتینری با digest
   `sha256:20263ce025b2…` اجرا می‌کند که از commit `b34647e166cd7a0f8bb80d44c075a23faef0e8ce`
   ساخته شده — ۱۴ commit و ۶۴ فایل `apps/admin` پیش از `540fbf9`. یعنی هیچ‌یک از مراحل ۷ تا ۱۱
   روی Production نیست. تا ساخت و استقرار image از commit انتشار، آنچه تأیید شده و آنچه اجرا
   می‌شود دو چیز متفاوت‌اند.

**دو ادعای P0 نسخهٔ نخست رد شدند:**

| ادعای رد‌شده                                              | واقعیت اندازه‌گیری‌شده (۲۰۲۶-۱۰-۱۲، فقط‌خواندنی)                                                                                                                                                                         |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| «migrationهای ۰۰۲۴ تا ۰۰۳۴ روی Production اعمال نشده‌اند» | **۳۴/۳۴ اعمال شده‌اند.** head ledger = `0034_admin_pack_metadata_grants`، اعمال ۲۰۲۶-۱۰-۱۰ ساعت ۱۸:۲۶:۱۶Z. sha256 هر فایل با checksum ثبت‌شده یکی است: صفر فایل بدون سطر، صفر سطر بدون فایل، صفر عدم‌تطابق، بازهٔ پیوسته |

دوباره اندازه‌گیری نشد — و نام جدول از نام فایل migration حدس زده شد، نه از محتوای آن.

### P1 — مانع کار عادی Admin

2. **جایگزینی اسپلش بدون ذخیره‌سازی خصوصی کار نمی‌کند (LB-B56) — محدودتر از نوشتهٔ نخست.**

   می‌بندد: مسیر اسلایدر بایت‌ها را در `banners.image_data` (bytea، درون دیتابیس) نگه می‌دارد و

3. **هیچ تأیید واقعی کاربر روی Production نیست — با یک اصلاح.** روی Production فعالیت واقعی
   اپراتور ثبت شده (`admin_sessions`=۱۲، `audit_logs`=۵۶، آخرین ۲۰۲۶-۱۰-۱۰ ساعت ۱۶:۴۲)، ولی همه
   روی image پیش از مرحلهٔ ۷. هیچ اپراتوری UI مراحل ۷ تا ۱۱ را ندیده است. این مورد فقط با یک
   اپراتور واقعی و Passkey واقعی روی دامنهٔ Production **پس از** استقرار بسته می‌شود.
4. **آرشیو پشتیبان نقش و grant ندارد.** dump شبانه صفر خط `GRANT` و صفر `CREATE ROLE` دارد، و
   پنجرهٔ PITR نئون روی این پلن ۶ ساعت است (`history_retention_seconds = 21600`). رویهٔ بازیابی
   کامل و drill اثباتی‌اش اضافه شده‌اند (`docs/operations/BACKUP_RESTORE.md` و
   `learnbox-recovery-drill.sh`؛ اجرای ۲۰۲۶-۱۰-۱۱ روی آرشیو واقعی: PASS، ۴۶ بررسی) ولی خود
   اسکریپت و timerش **روی هاست نصب نشده‌اند** و آرشیوها فقط روی دیسک همان هاست‌اند.

## ۷. پیش‌نیازهای بازگشت

1. هر مرحله یک squash commit مستقل است؛ `git revert <sha>` کافی است.
2. **نقطهٔ بازگشت image، ثبت‌شده:** `sha256:20263ce025b239213a4f181f1816d0b967a53866984b21da55c2052dd0dd27cd`
   (tag `learnbox-admin:b34647e-pack-metadata`، commit `b34647e166cd7a0f8bb80d44c075a23faef0e8ce`).
   بازگشت = استقرار دوبارهٔ همین digest و حذف پرچم‌های تازه‌روشن‌شده. سه image قدیمی‌تر Admin هم
   روی هاست مانده‌اند، از جمله `dcd82d7-step-up-reauth` (`49c9d2e9a30b`).
3. هیچ migration ای در این انتشار نیست، پس بازگشت schema لازم نیست. head روی `0034` می‌ماند.
4. learner با compose جدا مستقر می‌شود و در هیچ سناریوی بازگشتی لمس نمی‌شود
   (`sha256:65cd79695c1c…`، دست‌نخورده).
5. **نقطهٔ بازگشت دیتابیس:** branchهای نئون `prod-pre-0034-20261010T1815Z` و
   `prod-pre-0033-20261009T2035Z`، به‌علاوهٔ آرشیو شبانه. برای بازیابی کامل — شامل نقش‌ها و
   grantها که dump ندارد — رویهٔ `docs/operations/BACKUP_RESTORE.md` → «Recovering the whole
   database» و اسکریپت `learnbox-recovery-drill.sh`. پنجرهٔ PITR فقط **۶ ساعت** است؛ بعد از آن
   تنها مسیر، آرشیو + بازسازی نقش از مخزن است.
6. پیش از پنجرهٔ استقرار یک dump تازه و یک branch تازه گرفته شود، نه فقط تکیه بر آرشیو شبانه.

3. هر ۹ مقصد ناوبری باز شود بدون ۵۰۰ و بدون صفحهٔ خالی.
4. داشبورد اعداد واقعی نشان دهد یا «در دسترس نیست» — هیچ عدد بی‌منبع.
5. مشاهدهٔ Audit log و ثبت‌شدن همین نشست در آن.
6. یک چرخهٔ کامل بسته: ساخت پیش‌نویس، بازبینی، انتشار — سپس بازگشت وضعیت.
7. فروشگاه و تراکنش‌ها بارگذاری شوند بدون فعال‌شدن هیچ درگاه پرداختی.
8. عرض موبایل روی یک دستگاه واقعی: ناوبری قابل رسیدن، بدون سرریز افقی.
9. **تأیید هویت image پس از استقرار:** `APP_SOURCE_SHA` کانتینر و label
   `org.opencontainers.image.revision` هر دو با commit انتشار برابر باشند.
10. learner دست‌نخورده: digest همان `sha256:65cd79695c1c…` و بدون restart.

شرط بازگشت: هر کانتینر `unhealthy`، هر حلقهٔ restart، یا هر ۵xx در یکی از ۹ کارگاه.

## ۱۰. ارزیابی

کد Admin از نظر UI، دسترس‌پذیری و رگرسیون قابل‌استقرار است: ۸۹۳ تست در ۷۸ فایل با دیتابیس
واقعی سبز، بدون skip؛ typecheck، lint، format و هر پنج گیت مرزی سبز.

**دیتابیس بازدارنده نیست.** schema روی `0034` است و بایت‌به‌بایت با مخزن می‌خواند، و
`learnbox_admin` دقیقاً همان مجوزهایی را دارد که لازم است و هیچ‌یک از مجوزهای خطرناک را ندارد.
دو ادعای P0 نسخهٔ نخست، رد شدند.

آنچه مانده:

- **P0 — image کهنه.** بسته شد به‌عنوان آمادگی: image انتشار از commit ادغام ساخته و تأیید شد
  (`sha256:bfb9db8c…`، ۱۰ بررسی). باز می‌ماند به‌عنوان _استقرار_، چون استقرار مجاز نیست.
- **P1 — تأیید اپراتور واقعی.** فقط پس از استقرار قابل بستن است (بخش ۹).
- **P1 — نصب اسکریپت بازیابی روی هاست و نسخهٔ خارج از هاست آرشیوها.** رویه و اثباتش آماده است؛
  نصب روی هاست یک تغییر Production است و مجوز جدا می‌خواهد.
- **P1 — جایگزینی اسپلش (LB-B56).** تصمیم مالک دربارهٔ ذخیره‌سازی خصوصی؛ اسلایدر تحت تأثیر نیست.

**توصیه: GO برای آماده‌سازی انتشار (همین PR). NO-GO برای استقرار امروز** تا مالک یک پنجرهٔ
استقرار را جداگانه تأیید کند. ترتیب امن در بخش‌های ۷ تا ۹ آمده است.
