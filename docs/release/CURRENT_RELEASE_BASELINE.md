## Pack membership reconciliation — 2026-09-27 (candidate only)

**Classification: C — accidental schema divergence (and a missing tracked migration), not a prototype-only `pack_cards` table.** Read-only SQL against the configured Neon `neondb` database, inside `BEGIN READ ONLY`/`ROLLBACK`, found `packs` and `pack_cards` in `public`: one published/free starter pack (`learnbox_start_a1_essentials`) with 35 members, 35 published versions, 35 distinct `start-a1-*` cards, zero membership orphans, and 35 matches between `cards.content_id` and published `content_json.id`. `pack_cards` has `(pack_id, card_id)` primary key and foreign keys to `packs(id)` and `cards(id)`; `sort_order` defaults to zero. These tables are used by newer Admin pack handlers and learner Words/Progress/Today/Profile handlers. Removing the relationship would break the current DB-backed flow; adding a second relationship would duplicate it.

The production `schema_migrations` ledger has versions `0001`–`0017`; all 17 checksums match this candidate's SQL. **None of those migration files creates the two pack tables.** Repository-wide and Git-history searches found no `CREATE TABLE packs`/`pack_cards` migration. The exact out-of-band creation event is unknown. ADR 0013 explicitly deferred pack membership, and ADR 0016 prohibited creating it as part of its earlier seed gate; neither is evidence to erase the later live relationship.

Candidate-only migration `0018_pack_membership_schema.sql` records the observed existing shape, creates the two tables on a genuinely clean database, fails closed on incompatible pre-existing shapes/keys, and does not seed, publish, delete, or update content. An isolated fresh PostgreSQL 16 run applied all 18 migrations, re-ran them with zero additional applications, and produced both tables with zero pack rows. **Migration 0018 has NOT run against Production.** Before any owner-authorized production application: take a verified backup, recheck the live schema/ledger and DDL, exercise a data-preserving staging copy and rollback/recovery procedure, and confirm no concurrent writer or unpublished state would be affected. This reconciliation establishes schema shape, not a completed learner E2E or release authorization.

### Phase 5 account and presentation findings (candidate, not deployed)

The prototype auth flag now defaults to real OTP outside isolated tests. Browser-local review queues, personal words, daily progress, goal, session index and streak are keyed by the server session subject before being read; the reviews POST additionally rejects an owner-header/session mismatch. **Old unscoped local keys are retained and deliberately not auto-attributed to any account.** Unscoped legacy localStorage entries are quarantined in place: the release runtime neither reads them into an authenticated account nor deletes, renames, submits, or silently claims them. Keep a recoverable device/profile backup before any cleanup; the eventual claim flow must require a verified same-account owner decision, show a per-key preview and count, preserve an export/rollback copy, and reject review-event ID collisions or mismatched server acknowledgements. The browser's old unscoped key alone cannot prove who created an answer, so no automatic ownership inference is permissible. An owner-preserving recovery UX for previously unsynced answers remains a release blocker; this is not permission to abandon the data. The learner Today screen shows unavailable markers rather than fabricated zeros when its server read fails. The v1 banner endpoint filters out Production's live store/promotion banners while paid packs are out of scope. Local authenticated media probes use a signed synthetic development session with real read-only Production content, **not** a completed OTP/account E2E.
