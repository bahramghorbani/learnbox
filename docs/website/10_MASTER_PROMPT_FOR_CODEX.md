# Master Prompt for Codex

Read every file in `docs/website/` before implementation.

Your task is to build the official LearnBox public website and cinematic landing experience inside the existing LearnBox repository.

Do not create a new repository.

Start by auditing the repository and identifying the safest integration point.

Follow these non-negotiable rules:

1. Do not rebuild existing work.
2. Reuse and validate existing branding, components, infrastructure, and BuBu assets.
3. If a valid BuBu section exists, do not recreate or overwrite it.
4. Add DuDu only if missing, using the supplied approved reference image.
5. Use the official English names `BuBu` and `DuDu`.
6. Build the website as a formal subproject of the main LearnBox repository.
7. Keep the website separate from the app admin panel and management interface.
8. Implement the project according to the numbered storyboard and roadmap.
9. Do not leave multiple half-built scenes. Complete work in order.
10. Maintain `PROJECT_STATE.md` and `CHANGE_REQUESTS.md`.
11. After any requested change, automatically return to the saved roadmap resume point.
12. Make routine reversible decisions independently.
13. Involve the user only when access, credentials, payment, DNS, secrets, irreversible publication, or major brand decisions require it.
14. Give non-technical step-by-step instructions when user action is unavoidable.
15. Use free and mature motion tools where possible.
16. Prefer GSAP for cinematic scroll timelines and Motion for React for UI transitions.
17. Keep the complete static experience usable without complex motion.
18. Support reduced motion and mobile-specific motion profiles.
19. Centralize content, links, release statuses, social URLs, and themes.
20. Do not claim unsupported product features or platform availability.
21. Test, debug, document, preview, deploy, and verify production.
22. Do not stop after scaffolding.
23. The valid finish state is:

```text
LearnBox Website v1.0
Status: COMPLETE
Production: VERIFIED
```

Begin with a repository audit. Then create or update the project state file and proceed through the roadmap without requesting routine confirmation.
